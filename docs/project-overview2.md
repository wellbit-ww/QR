# Портал SOVA: шпаргалка к защите

Документ для человека, который **первый раз видит этот репозиторий**, но через неделю должен **защитить проект**: объяснить задачу, архитектуру, почему так, где слабые места и что ответить на типовые вопросы.

Предполагается, что RAG, REST, Postgres и LLM вам уже знакомы. Здесь — как **конкретно это** собрано, а не курс по эмбеддингам.

Код: сентябрь 2026. Узко про 1106 — [RAG-SDB1106NM.md](./RAG-SDB1106NM.md). Выкладка — [nginx-reverse-proxy-setup.md](./nginx-reverse-proxy-setup.md).

## 1. Что защищаете, одной минутой

**Продукт:** внутренний (и полевой) портал сервисной поддержки шкафов сухого хранения Совтест АТЕ. Бренд чата — SOVA.

**Сценарий:** QR на шкафу → логин → карточка **этой** модели → чат по руководству по эксплуатации (РЭ) → при необходимости заявка в техподдержку на почту.

**Не продукт:** универсальный ChatGPT, поиск по интернету, мультиагент, fine-tune весов по PDF.

**Тезис, который надо удержать:**  
шкафы серии SDB похожи по устройству и тексту РЭ, но **цифры разные**. Ошибка «70 кг вместо 90» или «выключите во время регенерации» — это не UX-баг, а производственный риск. Поэтому система — **не «LLM + PDF»**, а конвейер с жёсткой изоляцией модели, каталогом паспортных фактов и RAG только там, где шаблона нет.

Четыре шкафа в каталоге:

| Catalog id | Шильдик | Knowledge | Запомнить |
|---|---|---|---|
| `w-700` (public `sdb302-nm`) | SDB302NM | `knowledge/w-700/` | Исторический id; снаружи 302 |
| `sdb702-nm` | SDB702NM | `knowledge/sdb702-nm/` | 743 л, 90 кг, 7 полок, 3 двери |
| `sdb151-nm` | SDB151NM | `knowledge/sdb151-nm/` | Свой фильтр контекста |
| `sdb1106-nm` | SDB1106NM | `knowledge/sdb1106-nm/` | Самый развитый golden-router, 180 кг |

Если спросят «почему w-700»: легаси идентификатор, не отдельный продукт.

## 2. Задача и ограничения (с этого начинают защиту)

**Кто пользователь.** Оператор / наладчик / сервис, не дата-сайентист. Пишет как говорит: «огонёк», «не обожгусь», «на обед вырубить».

**Источник истины.** РЭ конкретной модели. Карточка на сайте (`data/equipment.json`) может содержать маркетинговые цифры (влажность «1–50%»). В РЭ часто **0–80 RH%, не выше окружающей**. На защите говорите: *чат обязан расходиться с витриной, если витрина не совпадает с РЭ*.

**Ограничения, которые объясняют стек:**

1. **On-prem / локальный LLM.** Ollama на `127.0.0.1:11434`. Нет отправки РЭ в облако.
2. **Несколько близких моделей оборудования.** Retrieval **обязан** фильтровать `equipment_id`. Иначе 302 украдёт 743 л у 702.
3. **Безопасность.** Дым → обесточить, не «проверьте уплотнители». Регенерация → **запрещается выключать**.
4. **Аутентификация.** Учётка привязана к списку шкафов. Чат чужой модели — 403.
5. **Железо.** Генерация — `qwen2.5:32b-instruct`; эмбеддинги — `bge-m3` (вектор **1024**). Лёгкая модель `llama3.1:8b` — служебные вызовы (rewrite / fallback-классификация).

LangChain и облачный API **намеренно не используются**: нужен полный контроль над порядком gate → facts → retrieve → generate → post-gate.

## 3. Картина на доске

Три процесса (могут быть на одной машине):

```
Браузер ──HTTPS (Nginx)──► Node.js :3000
                              │
                              ├── PostgreSQL :5432   сессии, users, knowledge_chunks
                              └── Ollama     :11434  embed + chat
```

Снаружи в бою только 443. Postgres и Ollama не публикуются.

**Слои приложения:**

| Слой | Где | Роль |
|---|---|---|
| Витрина | `public/` + `data/equipment.json` | HTML, карточка, PDF |
| HTTP | `server.js` (Express 5) | `/api/chat`, логин, support |
| Профиль шкафа | `src/equipment/profiles/` | Свой gate / facts / post-gate |
| RAG-ядро | `src/rag/` | Роутер, hybrid search, промпты, guardrails |
| Знания | `knowledge/<id>/` | РЭ, golden-facts, у 302 ещё retrieval-cards |

Фронт — **ванильный JS**, не SPA-фреймворк. На защите: *объём UI маленький, сессии и политика безопасности важнее реактивного стора*. Markdown ответа: `marked` + `DOMPurify`.

## 4. Конвейер `/api/chat` (это надо рассказывать наизусть)

Файл входа: `server.js` → `POST /api/chat`. Дальше — профиль шкафа и при необходимости `src/rag/pipeline/run-pipeline.js`.

```
1. Auth + ACL          учётка имеет этот equipmentId?
2. Pre-gate            чужая модель / оффтоп / Wi-Fi / контакты → готовый текст, LLM нет
3. Deterministic facts regex-каталог ТТХ и аварий → готовый текст, LLM нет
4. RAG pipeline        роутер → (опц. rewrite) → hybrid retrieve → decision → Qwen
5. Guardrails          заземление, эвристика «лишних» слов
6. Post-gate           подмена/отсечение утечки артикула, опасных советов
7. HTTP 200            один ответ; канал (facts vs RAG) в UI не светится
```

### Зачем каждый слой (готовые формулировки)

**Pre-gate.** LLM с радостью ответит про борщ и про массу соседнего шкафа. Для портала с QR на железе это недопустимо. Реализации: `sdb302nm-chat-gate.js` и аналоги. Действия: `OFF_TOPIC`, `FOREIGN_MODEL`, `UNSUPPORTED_SPEC`, `CONTACT_SUPPORT`, `IN_SCOPE`, `SAFETY`.

**Deterministic catalog.** Паспорт (70 кг / 90 кг / 180 кг, литры, полки) и аварии не должны зависеть от retrieval. Модули `*-direct-facts.js`. Если матч сработал — **Ollama на ответ не зовут**. Latency и воспроизводимость — аргумент на защите.

**RAG.** Живые и процедурные вопросы («дверь не дожимается», «SET нажал — дальше что») плохо закрываются одним regex. Тогда hybrid search + генерация **строго по найденному контексту**.

**Post-gate.** Второй предохранитель: RAG всё равно может утащить SET +40 °C на вопрос про корпус ~100 °C. Профиль может вернуть канонический факт.

**Честный тезис:** это гибрид rule-based expert system и RAG. Нападать будут фразой «у вас же не ИИ, а if’ы». Ответ: *ИИ — для хвоста распределения вопросов; голова распределения (ТТХ, ТБ) закрыта правилами, потому что цена ошибки выше цены гибкости.*

## 5. Retrieval: что сказать, если спросят «как ищете»

Инжест: `npm run ingest:knowledge` → таблица `knowledge_chunks`.

- `equipment_id` — обязательный ключ изоляции;
- `embedding VECTOR(1024)` — bge-m3;
- `content_tsv` — FTS, конфиг **`simple`**, не `russian`: стеммер выкидывает токены вида `SDB1106NM`;
- индекс `ivfflat` по cosine.

Нарезка по умолчанию **parent–child**: child ~1500 символов для поиска, parent ~6000 в контекст LLM (`src/rag/config.js`).

Запрос:

1. Embed вопроса.
2. kNN по вектору.
3. FTS по словам.
4. **RRF** (k=60, гибрид). Аббревиатуры ГОСТ/IP/RH/Вт могут усилить лексическую ветку.
5. **Rule-based rerank** (`src/rag/rerank.js`) — не cross-encoder. Бонусы за раздел РЭ, единицы, для 302 — файлы `retrieval-cards/`.

Если спросят «почему не BM25-сервер / не Cohere rerank»: *один Postgres, объяснимый rerank, нет ещё одного сетевого сервиса; качество ловим eval-наборами, не лидербордом MTEB.*

Порог сходства ~0.28, с послаблениями для процедур / ТО / safety, чтобы не абстейнить, когда куски есть, но скор средний (`decision-engine.js`).

## 6. Стек — не список npm, а обоснование

| Выбор | Чем защищать |
|---|---|
| Express 5, без Nest | Один процесс, предсказуемый пайплайн чата, мало абстракций |
| Helmet + session в Postgres | Портал с логином; рестарт Node не должен убивать сессию |
| 100 req / 15 мин на `/api/chat` | Защита GPU/Ollama, не DDoS-маркетинг |
| pgvector в том же Postgres | Сессии и векторы в одной БД, Docker один сервис |
| Ollama, не API OpenAI | РЭ не уезжает в облако; железо своё |
| Qwen 32B instruct | Русский РЭ, локально; температура ~0.1 |
| bge-m3 | Многоязычный dense, размер 1024 зашит в схему |
| Свой пайплайн, не LangChain | Порядок слоёв — продукт; фреймворк скрыл бы gate/facts |

Парсеры документов: Python PDF→Markdown (таблицы), fallback `pdf-parse`; Word — `mammoth` / `word-extractor`.

Почта: `nodemailer` + SMTP Совтеста. Вложения формы — `multer`.

## 7. Мультимодель: главный архитектурный риск

Общий код (`retrieval.js`, `chunking.js`, `rerank.js`) **общий**. Различие — профиль:

- pre-gate / facts / post-gate / section hints;
- у 302 ещё pin retrieval-cards.

**Правило, которое надо произнести:** правки 302 в shared-файлах только за `equipmentId === "w-700"`. Иначе регресс 702/151/1106.

Эмпирически (прогон 125 одинаковых живых вопросов, экспертная оценка, сентябрь 2026): 302 ≈ **108/125** верно, 702 ≈ **77/125**. ТТХ у обоих свои, утечек литров/кг не было. Разрыв — на разговорных формулировках, которые 302 закрыл фактами и карточками, а 702 ещё нет. На защите это плюс (изоляция работает) и минус (качество не «бесплатно переносится» на соседнюю модель).

## 8. Как доказываете качество

Не LLM-as-judge на проде. Схемы:

- **Юнит-профили:** `npm run test:sdb302nm` и аналоги — deterministic + gate без сервера.
- **Live eval:** `scripts/eval-rag.js` бьёт в `/api/chat`, пишет `data/eval-*-results.json`. Keyword `mustContain` / `mustNotContain` — грубый фильтр; **экспертная** оценка нужна для «частично / отказ / подмена факта».
- **1106 parity:** Direct context vs RAG, цель ≥ 95% (`npm run eval:parity`).

Наборы лежат в `data/eval-*.json`. Для 302 эталонный «боевой» набор — 125 вопросов (карточки + разговорный слой).

Если спросят «какая точность»: *не один процент на все шкафы; называйте конкретный прогон, дату и способ оценки. Keyword-score ~0.99 обманывает — почти любой отказ содержит стоп-слова.*

## 9. Слабые места (лучше сказать самим)

1. **Каталог фактов растёт regex’ами.** Новый живой вопрос часто = новое правило. Это техдолг; альтернатива — дообучать retriever/reranker, её сознательно откладывали.
2. **Rerank эвристический.** Cross-encoder точнее на хвосте, дороже и хуже объясняется.
3. **Инжест ручной.** Поменяли РЭ — нужен `ingest:knowledge`, иначе чат на старых чанках. Рестарт Node подхватывает JS-факты, но не векторы.
4. **Матчеры воруют вопросы.** Пример: «опция подогрева, корпус 100 °C» попадал в правило SET +5…+40. Лечится более специфичным правилом выше по списку — типичный класс багов.
5. **Витрина vs РЭ.** `equipment.json` может врать относительно РЭ; это надо знать и не защищать витрину как истину.
6. **Direct vs RAG.** Без Postgres часть профилей кладёт большой кусок РЭ в промпт. В проде с БД основной путь — RAG.
7. **Нет единого «мозга» на все шкафы.** Перенос карточек 302 на 702 — отдельная работа, не конфиг.

## 10. Вопросы, которые зададут, и каркас ответа

**Почему не просто загрузить PDF в ChatGPT?**  
РЭ похожи между моделями, облако недопустимо, нужны отказ «не указано», ТБ и ACL. GPT без изоляции `equipment_id` смешает 302 и 702.

**Это RAG или экспертная система?**  
Оба. Head: facts + gate. Tail: RAG. Метрика успеха — не «доля вызовов LLM», а отсутствие ворованных ТТХ и опасных советов.

**Где гарантия, что 32B не выдумает?**  
Нет гарантии. Есть: узкий контекст одной модели, grounding, post-gate, каталог на числах, eval. На числах LLM по возможности обходим.

**Почему Qwen, а не GPT-4?**  
Локальность РЭ, предсказуемый runtime, нет vendor lock на токены. Качество дожимаем retrieval и фактами, не сменой API.

**Как добавите пятый шкаф?**  
Карточка в `equipment.json`, папка `knowledge/<id>/`, профиль в `src/equipment/profiles/`, регистрация в `equipment-runtime.js`, инжест, eval-набор. Shared retrieval не копировать вслепую.

**Пользователь обошёл логин?**  
В production `AUTH_REQUIRED=1`, слабый `SESSION_SECRET` не даст стартовать. Cookie session, store в Postgres.

**Что с персональными данными?**  
Чат про оборудование. Заявки support — SMTP на ящики Совтеста. Политика — черновик в `docs/portal-privacy-policy-draft.md` (не путать с технической архитектурой).

## 11. Карта репозитория на вечер перед защитой

Читать в таком порядке:

1. `server.js` — `POST /api/chat` (gate → facts → `runPipeline` → post-gate).
2. `src/equipment/equipment-runtime.js` — как выбирается профиль.
3. Один профиль целиком, например `src/equipment/profiles/w-700.js` + `sdb302nm-chat-gate.js` + `sdb302nm-direct-facts.js`.
4. `src/rag/pipeline/run-pipeline.js` + `retrieval/unified-retriever.js` + `retrieval.js` (RRF).
5. `src/rag/config.js` — все флаги RAG_*.
6. `scripts/ingest-knowledge.js` — от файла до `knowledge_chunks`.
7. `data/equipment.json` vs `knowledge/*/golden-facts-*.md` — конфликт витрины и РЭ.

Запуск стенда (чтобы не забыть на вопросе «а как воспроизвести»):

```text
Node ≥ 22.19, Docker, Ollama (bge-m3, qwen2.5:32b-instruct)
docker compose up -d
.env из .env.example → POSTGRES_URL, SESSION_SECRET
npm install && npm run ingest:knowledge
создать пользователя портала
npm start → 127.0.0.1:3000
```

Без инжеста факты из JS ещё живут, поиск по РЭ — нет.

## 12. Закрытие на 20 секунд

Портал SOVA — on-prem чат по РЭ шкафа, выбранного в сессии. Express отдаёт UI и `/api/chat`; Postgres хранит пользователей и чанки с векторами; Ollama считает эмбеддинги и пишет текст. Перед моделью стоят изоляция шкафа, отказ по чужим темам и каталог паспортных/аварийных фактов; RAG подхватывает остальное гибридным поиском. Так сделано не из недоверия к LLM вообще, а из того, что **у четырёх почти одинаковых руководств цена перепутанной цифры выше, чем цена лишнего правила в коде.**
