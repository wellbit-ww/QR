## Stage D — Chunk-level observability

**Root cause (Task 30):**

1. `EVAL_CAPTURE_RAG_TRACE` set only in **runner** process → pipeline on **server** never added `promptChunkSummaries`.
2. `extractSources()` never included `content` → diagnostics always `chunkTextCount: 0`.

**Changes:**

| File | Change |
|------|--------|
| `src/rag/eval-capture.js` | Request-scoped capture flag |
| `server.js` | `runWithEvalCaptureRagTraceAsync(evalTrace, …)` + `evalCaptureRagTrace` into `runPipeline` |
| `src/rag/pipeline/run-pipeline.js` | `sourcesFromPromptChunks(..., captureTrace)` with bounded `content`; chunk summaries when capture on |
| `scripts/sdb1560m-eval-runner-lib.js` | `fusedChunkTraceCount` in `evidenceUsed` |

**Operator requirement:** Restart portal after deploy; send eval with header `X-Sova-Eval-Trace: 1` (runner already does). Optional: `EVAL_CAPTURE_RAG_TRACE=1` in portal `.env`.

**Proof (Task 31 HTTP r2):** `logs/baseline-task31/task27-regression-http-verified-v2/eval-rag-diagnostics.jsonl` — non-zero `chunkTextCount`, `promptChunkTraceCount`, `fusedChunkTraceCount`; `sources[].snippet` populated when trace header on.

**Side effect:** Chunk bodies trigger **stricter overall scoring** via grounding layer (see HTTP section) — observability improved, headline pass rate dropped.

**Unit proof:** `testSourcesWithContentWhenCapture` in Task 31 test.
